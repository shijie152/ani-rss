# 03: 深化 RSS submission module：拆分提交、洗版与副作用

**What to build:** 保持资源提交、下载任务、洗版、历史记录、资源缓存和通知事件的现有行为不变，把“哪些资源应提交、删除或恢复”的决策收进 deep module，把下载器、历史、缓存和通知作为内部副作用 adapter；Coordinator 对外继续提供稳定 facade。

**Blocked by:** 02: 深化 RSS intake module：统一获取、解析与匹配流程

**Status:** ready-for-human

- [x] 已存在资源、已存在下载任务和重复 feed 结果仍保持幂等
- [x] 主资源与备用资源的洗版、替换、删除和 reconcile 规则保持不变
- [x] 下载器提交成功、响应丢失、提交失败、缓存失败和历史保存失败的部分失败语义可验证
- [x] 通知事件只在原有业务状态变化时触发，通知失败不会错误地重复提交资源
- [x] 外部网络调用不再被不必要的大范围锁长期包住，且不会引入并发重复下载
- [x] 决策 module 可使用内存 adapter 测试，下载器与持久化实现可独立替换

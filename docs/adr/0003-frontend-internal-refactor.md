# 前端可以在契约冻结下重构

ADR-0001 冻结的是 UI 对外使用的 **API 契约**（路径、HTTP 方法、参数、返回 JSON、认证方式），不是前端的内部结构。在保持这些契约不变的前提下，前端可以自由重构：抽取请求层与端点表、把散在各视图里的重复交互收进共享 module、替换废弃 API。

## Context

ADR-0001 的「现有 Vue UI 不修改」出现在 Go 后端迁移的语境里：当时的风险是前后端同时大改，出问题无法定位是哪一侧。那条约束防的是**契约漂移**，不是代码结构变动。

把「UI 不修改」读成「前端文件一行不能动」会挡掉必要的内部整理：请求去重曾在 `withQuery` 产出的带斜杠路径上静默失效，三个源站页各有一份逐字相同的批量添加与复制实现，视图里手写着缓存 TTL 与序列守卫。

## Considered Options

- 严格冻结前端源码：迁移期最稳，但已确认的缺陷（去重失效、四份重复实现）要一直带着。
- 前端自由改动（含契约）：风险回到 ADR-0001 想避免的「两侧同时变」，出问题难定位。
- 冻结契约、放开内部结构（本决定）：用一条自动化的契约测试兜住不变量，其余交给重构。

## Consequences

契约不变量由 `go-backend/internal/backend/route_parity_test.go` 守卫：它解析前端的端点表与 Go 的路由注册，逐条核对路径与方法，任一侧漏改就失败。端点表的路径与方法因此成为前端唯一真相源（`ani-rss-ui/src/js/endpoints.js`），改动 UI 调用面必须同时过这条测试。

前端内部（视图结构、请求层分层、共享 module 的接口）不再受 ADR-0001 约束；跨端契约本身的改动仍然需要单独评估，并另立 ADR 取代 ADR-0001 的对应部分（ADR 是记录，不改写）。
